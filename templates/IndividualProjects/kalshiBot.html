Kalshi Algorithmic Trading Bot

A live algorithmic trading bot placing real orders on Kalshi prediction markets.

  • Python
  • asyncio
  • Kalshi REST API
  • WebSockets
  • JSONL persistence
$3.6K+ live volume traded
4 market classes covered
Solo built and deployed

Overview

Kalshi is a regulated prediction market: contracts settle at $1 or $0 depending on whether an event happens. That makes it an unusually clean place to test an execution system: the payoff is binary, settlement is unambiguous, and the interesting edge sits in the last minutes before expiry, where prices drift away from what the underlying data already implies.

I built and deployed this bot end to end by myself. It has traded over $3.6K in live volume. Everything below runs against real money, which is the part that taught me the most: a bug here is not a failing test, it is a filled order.

Strategies

The bot runs several strategies concurrently, each with its own risk budget:

  • Near-expiry sports markets: contracts minutes from settlement where the live game state has effectively already decided the outcome.
  • Weather markets: temperature and precipitation contracts checked against forecast and observation data.
  • Economic markets: event contracts on scheduled data releases.
  • S&P 500 tail-bracket mispricing: far out-of-the-money daily brackets that stay bid above their fair value.

Execution and risk

The core is an async Python pipeline built on asyncio, combining Kalshi’s REST API for order placement with a WebSocket feed for live book updates. Orders go out immediate-or-cancel so the bot never leaves resting liquidity it did not intend.

Most of the engineering effort went into the things that keep it from losing money badly rather than the things that make it money:

  • Circuit breakers that halt trading when loss or error rates cross a threshold.
  • Per-strategy position limits, so one strategy misfiring cannot consume the whole book.
  • Liquidity gates that refuse to trade markets too thin to exit.
  • JSONL state persistence, so a crash mid-session recovers its open positions instead of waking up blind.

Settlement verification

Trading near expiry means the bot has to know whether an event has actually resolved, and it cannot just trust the market price to tell it. So I built an external outcome verifier that queries ESPN, weather.gov, Coinbase, and Yahoo Finance to independently confirm near-expiry settlement before the bot commits.

The edge cases here are where the real work lives. Each league has its own way of ruining a naive settlement rule, so the verifier carries per-league soft-locks: overtime guards for NBA and WNBA, outs-based settlement logic for MLB. I tuned all of it by reconciling against trades that had already settled, which surfaced failure modes I would never have guessed at from the API docs.
