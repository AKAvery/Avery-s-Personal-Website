The role

I spent the summer of 2026 as a software engineering intern at Chinstrap Ventures, working on Cossmology, a production React, TypeScript, and Supabase platform with real users. This was my first time in a codebase where my mistakes were visible to people who did not know me, and it changed how I write code more than any course has.

Over the internship I shipped 80 commits across 11 merged pull requests, each one through adversarial pre-promotion review.

DevOps overhaul

The platform did not have real environment separation when I arrived, which meant every change was a bet. I stood up proper dev, staging, and production environments using Supabase branching.

The harder half was keeping staging useful. A staging database that drifts from production stops catching the bugs you built it to catch, but one that is blindly overwritten loses the fixture data the team relies on for testing. I built a nightly production-to-staging sync in GitHub Actions on top of pg_dump that refreshes real data while preserving staging-only fixtures.

AI headline-research pipeline

I rebuilt the platform’s AI headline-research pipeline, a 2,000-line Supabase Edge Function. Three changes did most of the work:

  • Entity-pinned Exa neural search, so results stayed anchored to the entity being researched instead of drifting to topically similar but irrelevant coverage.
  • First-party domain capture, prioritising the source’s own site over aggregators.
  • Chunked parallel LLM-as-judge evaluation, which let the pipeline evaluate far more candidates within the same time budget.

Together these raised the candidate ceiling by 50%.

Admin curation console

The internal console the team used every day had accumulated the kind of problems that are individually small and collectively exhausting. I fixed 8 production bugs, added sorting and filtering across 10 fields, and rebuilt the edit flow around a reducer-based staged-edit store.

That last change is the one I am happiest with. The old console fired a request per keystroke-ish interaction and re-fetched the full table on every save, so slow responses arrived out of order and silently clobbered newer edits. Staging edits locally and committing them deliberately eliminated both the stale-response races and the full-table refetches.

Production incidents

I also handled live incidents. The one I remember best was a row-level-security gap that blanked the entire site for every logged-in non-admin user. That was the worst possible audience, since anonymous visitors and admins both saw a working site. Tracking that down taught me to distrust the fact that something works when I look at it.
